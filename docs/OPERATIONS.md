# Безопасность и эксплуатация

Снимок включает: проверку TLS и имени MySQL; CSRF; защищённые сессионные cookie; nonce для JS; ограничения входа 20 попыток/IP и 60/логин за 5 минут; проверку HTTPS-хоста и каждого редиректа записей звонков. Inline CSS оставлен для совместимости. Лимитер использует общий SQLite-файл вне публичного каталога; все Passenger-процессы должны видеть один файл.

Публикация ручная: проверить изменения/тесты, сравнить серверную версию, сохранить копию кода без секретов, загрузить полный согласованный комплект, перезапустить WSGI и проверить авторизованные страницы/API. Обязательно передавать `db_security.py` и `dashboard/login_security.py`. Пути и SSH-ключи действующего хостинга намеренно не включены.

`passenger_wsgi.py` в этом репозитории — переносимый шаблон. Он использует каталог файла либо `DASHBOARD_PROJECT_ROOT`; Python/virtualenv настраивается на стороне хостинга. Он отличается от конкретного серверного entrypoint, где были зашиты пути владельца. Проверить настройку до запуска.

При откате вернуть предыдущий комплект кода и перезапустить процессы; миграции и данные требуют отдельного плана отката. Секреты не брать из Git. Не публиковать production-выгрузки или реальные токены в Issues/PR.

## Известные ограничения для обсуждения

- Общая учётная запись; отдельных ролей и аккаунтов сотрудников нет.
- Отдельный ключ шифрования OAuth и зарегистрированный собственный callback требуют отдельной настройки/миграции.
- GET план–факта записывает служебные события/замечания; для сравнения без записи подменять обе функции sync_booking_events/sync_issues или использовать изолированную БД.
- Нет автодеплоя, строгого lock-файла зависимостей и готового demo seed.
- Лимитер рассчитан на процессы одного сервера. Для нескольких серверов потребуется общее хранилище.
- `X-Forwarded-For` не принимается как доверенный источник; используется REMOTE_ADDR. При изменении прокси проверить реальный клиентский IP.

Это перечень ограничений для обсуждения, а не созданные или согласованные рабочие задачи.
