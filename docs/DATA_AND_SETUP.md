# Данные и запуск

## Две исходные БД

`AMO_DB_*` — реплика amoCRM, OAuth и управленческие таблицы. `YCLIENTS_DB_*` — операционная/финансовая реплика YCLIENTS. Доступы к ним передаются отдельно от Git. Для разработки предпочтительна отдельная обезличенная копия; пустые схемы не дают содержательного отчёта.

`amocrm_schema.sql` описывает CRM-сущности, связи, историю этапов/тегов, звонки, OAuth и журнал загрузок. `docs/yclients-schema/schema.sql` и миграции `001`–`005` описывают компании, клиентов, визиты, услуги и финансовые сущности. В схеме также есть исходные идентификаторы филиалов для начальной настройки. Это исходные DDL проекта, не дамп текущего сервера: перед переносом сравнить фактический `SHOW CREATE TABLE` и применённые миграции.

Управленческие схемы:

| Файл | Назначение |
|---|---|
| `marketing_expenses_schema.sql` | Тарифы, расходы и аудит |
| `marketing_budgets_schema.sql` | Рекламные бюджеты |
| `marketing_budgets_history_schema.sql` | История бюджетов |
| `plan_fact_schema.sql` | Месячные планы, значения, события, замечания и аудит |

На подготовленной тестовой amoCRM-БД применяются скрипты:

```bash
python apply_marketing_expenses_schema.py
python apply_marketing_budgets_schema.py
python apply_marketing_budgets_history_schema.py
python apply_plan_fact_schema.py
```

Это операции записи в БД. Не запускать их на рабочей базе автоматически при старте приложения/тестов. Не менять схемы источников ради нового отчёта без отдельной миграции и проверки обратной совместимости.

## TLS и окружение

Оба DB_HOST должны соответствовать имени в доверенном сертификате. Системный CA используется по умолчанию; `*_DB_SSL_CA` задаёт собственный CA. `PREFERRED` в старых конфигах не отключает обязательную проверку нового кода. MySQL на localhost без TLS с этим приложением не совместим: подготовьте тестовую БД с сертификатом. Подмена DB_HOST на IP/SSH localhost может нарушить проверку имени.

Все параметры перечислены в `.env.example`. Генерация отдельного случайного ключа сессии на машине разработчика: `python -c "import secrets; print(secrets.token_hex(32))"`. Значение записать только в локальный `.env`. Для production обязательно `DASHBOARD_COOKIE_SECURE=true` и HTTPS.

## Загрузчик amoCRM

`python amocrm_loader.py --mode incremental` обновляет реплику; full-режим запускается отдельно осознанно. Сам скрипт не устанавливает cron. В коде есть блокировка параллельного запуска и журналы `amo_sync_*`.

Для первого запуска загрузчика необходимы OAuth-настройки и корректно инициализированная строка `amo_oauth_tokens`. Полного мастера OAuth-подключения в комплекте нет. OAuth-клиент также используется демонстрацией записей звонков. Пустой `.env.example` не предназначен для автоматического подключения к рабочей CRM.

Если уже сохранённые токены шифровались через AMO_CLIENT_SECRET, добавление нового AMO_TOKEN_ENCRYPTION_KEY без миграции сделает их нечитаемыми. Это отдельная согласованная операция.
